v1.4 (2026-10-11):
  - Room list (admin + reception) accepts `date` (yyyy-MM-dd, default today) and `search`
    (room number / type name); RoomResponse + RoomListItemResponse return `effectiveStatus`
    (Maintenance/Inactive physical, else Occupied when a live assignment covers the date, else
    Available). Status filter matches effective status for the date.
  - AssignRooms now rejects (409 booking.room_unavailable) a room already held by another
    Confirmed/CheckedIn booking with overlapping dates (BR-023).
  - Public anonymous cancel: POST /api/v1/bookings/cancel (rate limit lookup).
  - Transactional HTML emails (Application/Emails): booking confirmation, cancellation, payment
    receipt, check-in/check-out notice; SmtpEmailSender never throws (logs on failure).
v1.5 (2026-10-11) — operational policies (owner-approved; configurable, least-restrictive defaults):
  - Pending booking expiry: PendingBookingExpiryWorker (BackgroundService, Application layer) cancels
    Pending bookings older than Cancellation:WindowHours; interval Jobs:PendingExpiryIntervalMinutes
    (default 15). ActivityLog booking.expired (actor null) + BookingCancelled notification (account
    guests only); no email. Dormant under pay-at-hotel (nothing creates Pending yet).
  - Cancellation window (BR-024): free cancel only until Cancellation:WindowHours before the check-in
    day start (Africa/Lagos) -> else 409 booking.cancellation_window_closed (me + anonymous cancel).
  - Refund (BR-025): permitted cancel marks all Paid payments Refunded and sets PaymentStatus Refunded;
    cancellation email names the refunded amount.
  - Payment gates (7f): Settings:RequireFullPaymentAtCheckIn / RequirePaymentBeforeCheckOut (default
    false), DB-backed via Setting rows (no migration) + admin GET/PUT /admin/settings + Settings page;
    when on, check-in/check-out with balance outstanding -> 409 booking.balance_outstanding.
  - MailKit bumped 4.14.1 -> 4.16.0 (fixes NU1902 / CVE-2026-41319).
  - Integration tests: tests/Deutchezz.IntegrationTests/PolicyTests.cs (window, refund, gates).
All previously-missing services implemented (Staff management, Guests listing,

3. ROUTE / AUTH CONVENTIONS
---------------------------
- /api/v1 prefix, hyphenated resource names (room-types).
- /me/* = Customer; /reception/* = Receptionist+Administrator; /admin/* = Administrator.
- Policies defined (Wave 0): AdminOnly, StaffOnly, CustomerOnly. Controllers thin:
  inject I*Service, return result.ToActionResult().
- Scalar: Bearer security scheme + operation transformer attach "Authorize" only on
  endpoints that require authorization (anonymous endpoints stay unlocked).
- auth/logout and auth/me are Authenticated (no role policy).
